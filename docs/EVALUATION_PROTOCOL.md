# UCI prediction and evaluation contract

Use the end of the first nine months as the conceptual decision point. UCI describes predictors aggregated across those months and a binary customer state at the end of month twelve. The gap is approximately three months. Event dates, calendar cohorts, individual availability dates, censoring and interventions are absent. No exact 30-, 60- or 90-day horizon can be certified. Subscription length is tenure rather than survival time.

Pipeline v1 groups rows by all 13 canonical predictor values, excluding the target and generated ordinal. It orders groups by descending size with a SHA-256 tie-break derived from seed 20261127 and the predictor vector. It assigns the whole group to holdout when doing so decreases the sum of squared relative deviations from one fifth of each class total. The remaining groups form development. Grouping reduces exact-vector overlap, but distinct people may share a vector. A match on a subset of predictors or an unobserved shared customer is still possible. This is a grouped, approximately stratified snapshot split.

The approved Phase 2 interface is `retainiq.data.registry.development(root, dataset_id, version)`. It verifies artifacts and returns only development records, with labels outside features and ordinals reserved for traceability. Freeze the manifest/version and holdout checksum before analysis. Make internal validation folds in development using group constraints, fit all preprocessing, calibration, thresholds and hyperparameters there, then freeze the selected procedure. Open final holdout only for a documented final evaluation. Never select features or estimate intervention effects from full-corpus label associations.

Keep the full snapshot, membership and target records local. CLI profiles expose unconditional quality statistics and class totals only. Local administrators can inspect files directly; a stronger boundary requires a separate identity and storage location for final evaluation. Phase 1 trained no models.
